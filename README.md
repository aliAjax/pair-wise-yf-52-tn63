# pair-wise-yf-52 戏剧排练台词版本与舞台提示管控

## 源提示词摘要
导演、编剧、舞台监督和演员共同维护不同版本的剧本、角色台词、上下场提示、道具与灯光音效提示。编剧提交后需逐条合并，演员可查看最新版并标记疑问；支持版本对比、单条采纳、批注、冲突处理、排练模式、大字号提词和断网缓存。

## 技术栈
Angular + TypeScript + Angular Material + NgRx + Angular Router + RxJS + Angular CDK + Transloco。

## 已实现闭环
- 剧本版本和导演修订的创建、切换与版本差异摘要。
- 角色台词、舞台提示的采纳、退回和待确认状态。
- 排练模式、在线/离线切换与 localStorage 持久化。
- 未确认内容保留在草稿版本中，不会自动混入已采纳版本。
- **场次角色交接（版本化换人）**，详见下节。

## 场次角色交接（口头换人）

舞台监督只能口头换角时，系统按**场次版本**维护每次交接，入口在页面底部「场次角色交接」面板。

### 归属规则
- **读过的台词**固定记在读它的演员名下（`readByActorId` 一经写入不再改变），换人不带走。
- **未读台词**与**未执行的场记提示**随角色转给接替者。
- 演员**私下写的疑问只属于演员本人**，换人完全不转移。
- 每次成功交接，场次版本 `version +1`，并生成含「保留清单 / 转交清单 / 原因」的交接记录。

### 两个窗口同时换人
- 换人表单在打开时锁定所看到的**基准版本**；提交前会强制重读共享存储再比对。
- 晚到提交若发现基准版本之后**同一角色**已被交接，不会覆盖，而是返回逐条冲突列表（版本差 + 每一条已生效交接）。
- 若版本前进仅由**其他角色**的交接造成，则在当前版本上重放合并（审计中注明 rebase）。
- 验证方式：再开一个浏览器标签页（窗口名不同），两页对同一角色各自选人提交。

### 断网 / 保存失败 / 场次结束
- 断网提交的换人请求只留在**本窗口**的待发队列（不串窗口），网络恢复后按提交顺序、按场次版本合并；在线时每 4 秒也会自动重试。
- 模拟「下一次服务器保存失败」后，请求继续保留、记录尝试次数与错误，直到保存成功；中途再次失败则从当前项起全部保留。
- 冲突与拒绝都是**明确结果**：合并后从队列移除并写审计，不会无限重试。
- 场次结束后再提交（或离线排队、恢复后合并）都会得到「场次已结束」的明确拒绝。
- 面板「审计」与场次「交接记录」可查到每次交接、每次冲突/拒绝的原因、窗口与时间。

> 本项目用 localStorage 的共享键模拟多窗口共享的"服务器"（`yf52-handover-server`），用每窗口独立的键模拟本机队列（`yf52-handover-queue-<windowId>`），跨标签页通过 `storage` 事件实时同步。

## 测试
```bash
npm run test:handovers   # 37 项断言：归属分流、并发冲突、断网合并、保存失败重试、场次结束拒绝
```
测试为纯 Node 脚本（`.tests/`，自带 localStorage/Angular 垫片），不依赖浏览器。
